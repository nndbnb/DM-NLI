# Лабораторная работа №1 — вариант 1

Консольный верификатор шагов доказательства в исчислении высказываний.
Python 3.9 или новее. Внешние библиотеки не требуются.

## Схемы аксиом и правила

Используются переменные, константа ложности `f` и импликация `⊃`.

```text
A1: p⊃(q⊃p)
A2: (s⊃(p⊃q))⊃((s⊃p)⊃(s⊃q))
A3: ((p⊃f)⊃f)⊃p
```

Переменные в этих записях являются масками произвольных поддеревьев.
Все вхождения одной маски должны соответствовать одному и тому же дереву.
Разные маски независимы: они могут соответствовать как разным, так и
одинаковым деревьям. Имена переменных внутри найденного дерева не
сопоставляются повторно. Узлы импликации самой схемы и константа `f`
остаются фиксированными.

Например, сразу принимаются экземпляры A1:

```text
r⊃(s⊃r)
(r⊃s)⊃((t⊃f)⊃(r⊃s))
x⊃(x⊃x)
```

Во второй строке маска `p` соответствует дереву `r⊃s`, а маска `q` — `t⊃f`.
Строка `(r⊃s)⊃((t⊃f)⊃(r⊃u))` не соответствует A1: повтор `p` изменён.

Правила вывода:

- MP: из `A⊃B` и `A` выводится `B`.
- β: одна переменная во всех вхождениях заменяется одной и той же ППФ.
  Частичная подстановка и одновременная замена разных переменных запрещены.
  Константа `f` не заменяется.

Распознавание экземпляра схемы не является шагом β. Например,
`r⊃(s⊃r)` принимается сразу по A1, хотя из исходной записи A1 её нельзя
получить одной атомарной β-подстановкой. Ограничение β на одну переменную
продолжает действовать для уже доказанных формул.

По формулировке задания аксиомы доступны для MP и β с начала сеанса.
Также доступны все ранее принятые формулы. Проверяемая строка становится
источником только после успешной проверки.
Бесконечное множество экземпляров схем заранее не строится. Для MP
доступны три исходные записи и принятые строки; нужный дополнительный
экземпляр импликации сначала вводится отдельной строкой как аксиома.

## Синтаксис

Импликацию можно записывать как `⊃`, `->`, `=>`, `→` или `⇒`.
Переменные — латинские идентификаторы, например `p`, `q`, `x1`.
Пробелы игнорируются.

## Устройство программы

- `Variable`, `FalseConst`, `Implication` представляют узлы AST.
- `tokenize()` и `Parser` преобразуют строку в дерево.
- `find_beta()` проверяет полную подстановку одной переменной.
- `match_axiom_schema()` сопоставляет маски схемы с деревьями формулы.
- `ProofVerifier` хранит аксиомы, правила и историю с обоснованиями.
- `verify()` проверяет синтаксис, повтор, схемы аксиом, MP и β в этом порядке.
- Сравнение формул выполняется по структуре деревьев.

Неудачная проверка не меняет историю. Повтор ранее принятой формулы
не создаёт новую строку. Программа проверяет введённые шаги, а не ищет
полное доказательство автоматически.

## Запуск

Из корня репозитория:

```bash
python lab1/lab1_variant1.py
```

Команды: `axioms`, `list`, `clear`, `help`, `exit`.
`clear` очищает историю, сохраняя доступность аксиом.

Пример двух шагов без предварительного ввода A1:

```text
(p⊃(q⊃p))⊃(q⊃(p⊃(q⊃p)))
q⊃(p⊃(q⊃p))
```

Первый шаг — экземпляр схемы A1: `p` соответствует `p⊃(q⊃p)`, `q` — `q`.
Второй — MP из первого шага и A1.

Для воспроизведения примера сначала введите `clear`, затем обе строки
в указанном порядке, по одной на ввод. Не вводите номера шагов или Markdown.
При повторном вводе программа сообщит «уже доказана». Если после `clear`
ввести только вторую строку, она не будет принята: отсутствует первая посылка
для MP. Аксиома A1 при этом остаётся доступной.

Подробные входы и полные ожидаемые ответы, включая отказы:
[Сценарии проверки ЛР1](Сценарии_проверки_ЛР1.md).
Одна формула может иметь несколько корректных обоснований. Программа
выбирает одно по порядку проверки правил и доступных источников.
Поэтому формула, которую можно получить через β, будет помечена как
аксиома, если она уже соответствует одной из схем.

Пример β для формулы, которая не является аксиомой: после доказательства
`s⊃s` принимается `r⊃r` с заменой `s` на `r`. Полная цепочка доказательства
и ожидаемые ответы приведены в сценарии 20.

Отказ из-за недостатка посылок относится к одному шагу и не доказывает,
что формула ложна или недоказуема. При наличии подходящей импликации
сообщение называет недостающую посылку MP.

Для защиты от переполнения стека действуют лимиты: 20000 символов ввода,
100 уровней скобок и 100 уровней дерева. При превышении программа пишет
«Формула не проверена», сохраняет историю и продолжает работу.

## Тесты

Из корня репозитория:

```bash
python -m unittest discover -s lab1 -p "test_*.py" -v
```

Тесты проверяют синтаксис, левую группировку импликаций, скобки,
сохранение структуры при печати, допустимые и недопустимые β-подстановки,
маски всех трёх схем, одинаковые повторы масок, фиксированность `f`,
доступность аксиом, MP, ошибки ввода, повторы и очистку истории.
`test_demo_markdown.py` дополнительно запускает настоящий консольный интерфейс
по каждому сценарию Markdown и сравнивает полный ответ с ожидаемым.
Независимая семантическая проверка охватывает 155 построенных экземпляров
схем и все четыре двузначные оценки переменных a и b.

## Использование в ЛР2

Модуль `lab1_variant1.py` является общей основой обеих работ.
ЛР2 импортирует его типы AST, `Parser`, функции разбора, печати, сбора
переменных и `ProofVerifier` со схемами аксиом. Деревья передаются в
семантический анализ ЛР2 напрямую, без преобразования в другое представление.

В AST добавлены `Negation`, `Conjunction`, `Disjunction`. Расширенный разбор
включается явно: `parse_formula(text, extended=True)`. В обычном режиме
и в консольном верификаторе ЛР1 по-прежнему разрешены только импликация и `f`.
`match_axiom_schema()` и β обходят также расширенные деревья.
Во всех режимах `f` остаётся константой ложности.
