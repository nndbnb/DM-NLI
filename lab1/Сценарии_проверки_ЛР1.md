# Сценарии проверки лабораторной работы 1, вариант 1

Каждый раздел ниже — самостоятельный сценарий консольной программы.
Вводите только содержимое блока `input`, по одной строке, без обратных кавычек,
номеров и комментариев. Для следующего сценария запустите программу заново:

```bash
python lab1/lab1_variant1.py
```

В каждом блоке есть `clear` и `exit`. Они входят в проверку. Блок `expected`
содержит полный ожидаемый ответ после стартовой заставки, без приглашений
`formula> `. Строки сообщений не нужно вводить в программу.

Для автоматического прогона всех сценариев этого Markdown:

```bash
python -m unittest discover -s lab1 -p "test_demo_markdown.py" -v
```

Проверка запускает настоящий `main()` отдельным процессом для каждого раздела,
передаёт блок `input` в stdin и сравнивает stdout с блоком `expected` целиком.
Ожидаемые ответы заданы заранее, а не скопированы из результата запуска.

Для всех автоматических тестов:

```bash
python -m unittest discover -s lab1 -p "test_*.py" -v
```

Программа проверяет один шаг из аксиом и уже принятых формул. Она не ищет
полное доказательство, не считает таблицу истинности и не принимает гипотезы
просто по вводу. Отказ «Недостаточно данных» не означает, что формула ложна
или что её нельзя доказать другой цепочкой шагов.

Порядок выбора ответа: повтор → аксиома → MP → β → отказ. Если возможны
несколько обоснований, печатается одно по этому порядку. Новая формула
добавляется в историю только после успешной проверки. Ошибки и повторы
не занимают номера. Аксиомы доступны даже при пустой истории.

Это конечный набор основных граничных случаев, а не перебор всех формул.
Консоль игнорирует пустую строку; прямой вызов `parse_formula("")` выдаёт
ошибку синтаксиса. Имена `list`, `clear`, `help`, `axioms`, `exit`, `quit`
заняты командами в консоли. Формулы могут содержать эти идентификаторы
как часть выражения, например `list⊃(q⊃list)`.

## Результат проверки и исправления

Исходная версия взята из main репозитория nndbnb/DM-NLI:
`04a77d05386f64d8e18c75295764ce74bb076700`.
Сам двухшаговый пример README воспроизводится: β, затем MP.
Его повтор в том же сеансе даёт «уже доказана», а ввод только второй строки
в чистом сеансе получает отказ. Это различие контекста, не ошибка MP.

Выявленные недостатки исходной программы:

- При большой вложенности скобок происходил необработанный RecursionError.
- Отказ не пояснял, какая посылка отсутствует для MP, если подходящая
  импликация уже доступна.
- В истории появлялись сообщения «из аксиома» и «из строка».

Исправлено: добавлены диагностические сообщения о недостающих данных,
согласованы падежи в объяснениях, введены контролируемые лимиты
(20000 символов, 100 уровней скобок, 100 уровней дерева).
Лимит — отказ от проверки из-за ресурсов, а не утверждение об ошибке ППФ.
Исходные правила β и MP, доступность аксиом и порядок выбора правил сохранены.

Окончательные результаты автоматического прогона приведены в конце файла.
